`dist/` stops being source. Eighty-four built files leave the index, `.gitignore` covers `dist/`, and both CI jobs install the toolchain and run `npm run build` first, so the suites, the Pages snapshot and the publishing job all read output the build just produced. The pull-request job loses its `git diff --exit-code -- dist` reproducibility step: it existed only to keep two copies of the same site honest. `scripts/prepare-pages.mjs` now refuses an unbuilt checkout with an actionable message instead of failing inside `cp`, which a clone without `dist/` would hit immediately. Verified in a throwaway worktree of HEAD, which has no `dist/`: the guard fires before creating the output directory, and `npm ci` (19 packages) followed by `npm run build` reproduces the published site there byte for byte, `dist/index.html` included.

The guards that read published history are untouched, because history still holds those files: `site.mjs` and `service-worker.mjs` read `dist/index.html` and `dist/sw.js` from the pinned baseline, and `storage-compat.mjs` reads them from the pre-migration commit. Only new revisions need a build. `.openai/hosting.json` publishes the local `dist/`, and the hosting tool does not run build commands, so `DEPLOYMENT.md` now says the build must precede a preview — `npm test` already leaves a current `dist/` behind.

The authored worker is `src/sw.js`, copied verbatim into `dist/` (`cmp` clean), and its shell version moves `visual-edit-shell-editorial-gallery-v5` → `-v6`. The bump is required, not cosmetic: the migration rewrites every byte of the served HTML, and a returning visitor's installed worker serves the precached shell, so without a new version the previous page would keep loading offline until the worker happened to update.

- `npm run typecheck` (both programs) and `npm test`: exit 0. All fourteen suites green with zero page exceptions, including `service-worker.mjs`, `worker-storage.mjs` and `pages.mjs`.
